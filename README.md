# Галка: Планы и заметки

Ежедневник с напоминаниями для Android. Календарь, задачи по разделам,
локальные уведомления. Без аккаунтов, без сервера, без рекламы и аналитики —
данные лежат на телефоне и никуда не отправляются.

Версия **1.0.0**. Скачать APK: [Releases](https://github.com/ovnanime/galka/releases)

## Что умеет

**Календарь.** Месяц с цветными метками занятых дней. Тап по заголовку —
переход к любому месяцу и году. Под календарём лента дел выбранного дня:
сначала задачи со временем, отдельным блоком те, у которых времени нет.
Календарь сворачивается до одной недели.

**Задачи на любой набор дней.** У задачи не одна дата, а сколько нужно.
Дни выбираются календарём прямо в редакторе — тапом или ведением пальца.
Один день — разовая задача, несколько — она встаёт на каждый, и каждый
закрывается отдельно с прогрессом вида `3 / 7`. Есть готовые режимы:
единоразово, ежедневно, еженедельно, свой набор.

**Разделы.** Папки с цветом и описанием. Список задач показывается
по разделам или подряд по датам, с фильтром по разделам.

**Напоминания.** Четыре вида, каждый со своим временем и переключателем:
перед задачей со временем, список дел на день утром, отдельно о задачах
без указанного часа, вечерняя сводка незакрытого.

**Перенос данных.** Экспорт и импорт через файл `.galka`. Файл открывается
прямо из проводника. Удаление всех данных требует вписать слово и сначала
само сохраняет копию.

**Оформление.** Тёмная и светлая темы, семь цветов акцента.

## Установка

1. Скачать APK из [релизов](https://github.com/ovnanime/galka/releases).
2. Открыть файл, разрешить установку из неизвестных источников.
3. При первом запуске разрешить уведомления.

Дальше стоит зайти в настройки телефона → Приложения → **Галка** → Батарея
и поставить **Без ограничений**. На Xiaomi, Samsung и Huawei без этого система
усыпляет приложение, и напоминания приходят с опозданием или не приходят вовсе.

Проверить можно кнопкой «Прислать проверочное уведомление» в настройках —
оно отправляется сразу.

## Что где лежит

```
www/                 интерфейс, без сборщика
  index.html         разметка
  styles.css         оформление
  store.js           данные и localStorage
  notify.js          расписание уведомлений
  backup.js          обмен файлами .galka
  picker.js          свои окна выбора времени, даты и вариантов
  app.js             отрисовка и события
android/             нативный проект — его и открывать в Android Studio
store/               материалы для магазина и генераторы иконок
devserver.js         локальный сервер для предпросмотра в браузере
build-preview.js     сборка www/ в один файл (в APK не идёт)
update.json          сведения о последней версии для проверки обновлений
PRIVACY.md           политика конфиденциальности
```

Нативная часть — два файла: `MainActivity.java` (кнопка «Назад», открытие
файлов) и `AppSettingsPlugin.java` (уведомления, системные экраны, файлы,
резервная копия, выход).

## Задачи, дни и разделы

Сущностей всего две: **раздел** и **задача**. Отдельного объекта для
повторяющейся работы нет — и не нужно.

Дни одной задачи связаны общим `groupId`: на каждый день создаётся отдельная
запись в `tasks` с одинаковыми названием, разделом, временем и напоминанием.
Отличаются только `date` и `done`.

`Store.saveGroup()` принимает задачу целиком, вместе со списком дней:

- дни, оставшиеся в списке, сохраняют отметку о выполнении;
- снятые дни удаляются;
- добавленные создаются незакрытыми.

`Store.groups()` сворачивает записи обратно в задачи — это и есть то, что
показывает вкладка «Задачи». `deleteGroup()` убирает все дни разом.

### Совместимость данных

Ранние версии держали расписания релизов и циклов как отдельную сущность.
`Store.load()` при чтении убирает `project.release`, `project.cycle`
и `task.gen`, а каждой задаче без `groupId` выдаёт свой.

## Формат `.galka`

Синхронизации нет намеренно — она требует сервера и аккаунтов, а приложение
бесплатное. Перенос между устройствами и резервная копия делаются файлом.

Внутри обычный JSON с шапкой, читаемый глазами:

```json
{
  "format": "galka",
  "formatVersion": 1,
  "exportedAt": "2026-08-15T00:10:00.000Z",
  "app": { "versionName": "1.0.0", "versionCode": 1 },
  "counts": { "projects": 5, "tasks": 44, "groups": 13 },
  "data": { "projects": [], "tasks": [], "settings": {} }
}
```

Имя файла — `galka-ГГГГ-ММ-ДД.galka`.

**Экспорт** пишет файл в `cacheDir/export`, отдаёт его через `FileProvider`
и открывает системный выбор получателя. Каталог чистится перед каждой выгрузкой.

**Импорт** открывает системный выбор файла (`ACTION_OPEN_DOCUMENT` с типом
`*/*` — у `.galka` нет зарегистрированного MIME-типа). Файлы больше 8 МБ
отклоняются.

**Открытие из проводника.** Приложение объявлено обработчиком `.galka`.
Отбор идёт по имени файла, и шаблонов в манифесте четыре: `pathPattern`
не умеет повторять точку, поэтому для имён с точками нужен отдельный шаблон
на каждый уровень. Содержимое читается один раз — намерение сразу помечается
использованным, иначе тот же файл предлагался бы при каждом возврате.

**Резервная копия перед удалением всех данных** пишется без диалога сразу
в «Загрузки» через `MediaStore`: этот каталог переживает удаление приложения,
в отличие от собственной папки программы. До Android 10 копия кладётся
в каталог приложения на карте памяти.

### Что происходит с данными при импорте

`Store.readBundle()` только разбирает и проверяет файл, ничего не меняя:
отбивает повреждённый JSON, чужой формат, файл от более новой версии и файл
без задач. Пользователь видит, сколько внутри задач и разделов, и лишь потом
выбирает режим.

`Store.applyBundle()` умеет два режима:

- **добавить к текущим** — всем разделам, задачам и группам выдаются новые
  идентификаторы, связи перестраиваются, существующие данные не затрагиваются;
- **заменить всё** — данные очищаются и загружаются заново, с отдельным
  подтверждением.

Тема оформления при замене не перезаписывается — она относится к телефону,
а не к расписанию. Поля из файла санируются: цвета по маске, даты и время
по формату, длинные строки обрезаются.

## Оформление

Тема (`settings.theme`) — тёмная, светлая или системная. Цвет акцента
(`settings.accent`) выбирается отдельно, по умолчанию белый.

Каждый цвет задан парой значений: для тёмной темы и для светлой. Белый акцент
на светлой теме был бы не виден, поэтому там он превращается в почти чёрный.
`--accent-ink` остаётся из темы, поэтому подпись на цветной кнопке читается
при любом выборе.

Список цветов — `ACCENTS` в `store.js`.

## Уведомления

Идут через нативный `AlarmManager`, поэтому приходят и при закрытом
приложении. Каналы созданы с идентификаторами `reminders_v3` и `digest_v3`.

Про версию в имени канала: **Android не позволяет менять поведение уже
созданного канала.** Если канал завели без звука или с низкой важностью,
правки в коде на него не подействуют — помогает только новый идентификатор.
Старые каналы удаляются при запуске.

Расписание пересобирается при каждом изменении задач и при возврате
в приложение. Потолок — 300 будильников на задачи и по 14 дней сводок.

## Иконки

Собираются из `store/logo-source.png` скриптами:

```bash
node store/make-icons.js     # все размеры иконок
node store/preview-icon.js   # как это покажет лаунчер с круглой маской
node store/check-icons.js    # замер отступов и запаса до края маски
node store/analyze-logo.js   # разбор логотипа на связные области
```

Три вещи, которые пришлось учесть.

**Маска.** Лаунчер обрезает иконку, форма маски у всех разная.
Гарантированно видна только центральная окружность в 66,7% холста. Рисунок
вписан по описанной окружности, а не по габаритной рамке: у логотипа углы
пустые, и по кругу он выходит заметно крупнее при той же гарантии.
Проверка показывает 64,2% при пределе 66,7% — крыло не срежется.

**Подложка.** Прозрачным фон адаптивной иконки быть не может, Android всегда
его заливает. Чтобы вокруг круга не было белого кольца, подложка сделана
чёрной под цвет логотипа, а белая страница вокруг рисунка убирается заливкой
от краёв картинки — замкнутые белые области внутри при этом не задеваются.

**Календарь.** Он нарисован так же, как птица: чёрной заливкой с белой
обводкой, и на чёрной подложке сливался с фоном. По цвету их не различить,
но обводка делает календарь отдельной связной областью — заливка от точки
внутри него на птицу не переходит. Внутри календаря цвета переворачиваются:
корпус белый, клетки чёрные. Координаты точек заливки — `CALENDAR_SEEDS`
в `make-icons.js`, подбираются через `analyze-logo.js`.

## Подпись

Обновление обязано быть подписано тем же ключом, что и установленная версия,
иначе Android откажется ставить его поверх. Потеря ключа означает, что всем
придётся удалять приложение и терять задачи.

Ключ создаётся один раз и хранится вне репозитория:

```bash
& 'C:\Program Files\Eclipse Adoptium\jdk-17.0.1.12-hotspot\bin\keytool.exe' -genkeypair -v -keystore D:\Android\keys\galka-release.jks -alias galka -keyalg RSA -keysize 4096 -validity 10000
```

Рядом с проектом создаётся `android/keystore.properties`:

```
storeFile=D:/Android/keys/galka-release.jks
storePassword=пароль хранилища
keyAlias=galka
keyPassword=пароль ключа
```

Пути пишутся через прямую косую черту: обратную Gradle прочитает как
экранирование. И `.jks`, и `keystore.properties` перечислены в `.gitignore`.
Образца этого файла в проекте намеренно нет, чтобы пароль некуда было вписать
по ошибке.

Отпечаток сертификата:

```
SHA-256: d47a70456ac5aee8473ff1214d2271958bfc1070a2a3a586a03490f272af1ca7
```

`android/app/build.gradle` подхватывает пароли сам. Если файла нет, сборка
не падает: `release` просто остаётся без подписи.

## Сборка

Android SDK установлен в `D:\Android\Sdk`, путь прописан
в `android/local.properties`.

1. Открыть в Android Studio папку **`D:\Projects\dayplan\android`**
   (именно её, не корень проекта).
2. Задать каталог Gradle: *Settings → Build, Execution, Deployment →
   Build Tools → Gradle → Gradle user home* → **`D:\Android\gradle-home`**.
   Туда уже скачан Gradle 8.2.1 со всеми зависимостями.
3. Дождаться Gradle sync.
4. *Build → Generate Signed Bundle / APK* либо из командной строки:

```bash
cd D:\Projects\dayplan\android; .\gradlew.bat assembleRelease
```

Результат: `android/app/build/outputs/apk/release/app-release.apk`

Проверить подпись:

```bash
& 'D:\Android\Sdk\build-tools\34.0.0\apksigner.bat' verify --print-certs android\app\build\outputs\apk\release\app-release.apk
```

## Выпуск версии

1. Поднять `versionCode` и `versionName` в `android/app/build.gradle`.
   `versionCode` обязан расти, иначе установка поверх не пройдёт.
   `versionName` видит пользователь, `versionCode` — только Android.
2. Собрать `assembleRelease`.
3. Создать релиз на GitHub и приложить APK файлом.
4. Обновить `update.json`: `versionCode`, `versionName`, `notes`
   и `downloadUrl` со ссылкой на APK из релиза.

Приложение читает `update.json` с `raw.githubusercontent.com`, сравнивает
`versionCode` с установленным и предлагает скачать обновление. К адресу
добавляется уникальный параметр: CDN GitHub держит файл в кеше несколько
минут, и без этого свежий выпуск не виден сразу.

## Сборка для магазина

Магазины запрещают приложениям обновлять себя в обход магазина. Перед
сборкой для RuStore в `www/app.js` меняется одна строка:

```js
const DISTRIBUTION = 'store';   // раздел «Проверить обновление» скрыт
```

Дальше `npx cap sync android` и `assembleRelease`. После сборки значение
возвращается на `'github'`, иначе в версии для файловой раздачи пропадёт
проверка обновлений.

Тексты карточки, иконка и порядок подачи — в `store/rustore.md`.

## Разработка

```bash
node devserver.js
```

Открыть `http://localhost:5173`, править файлы в `www/`, обновлять страницу.
Уведомления в браузере не отправляются, файловые операции работают через
обычную загрузку и `<input type="file">` — предпросмотр остаётся рабочим.

После правок перенести изменения в нативный проект:

```bash
npx cap sync android
```

При правке `www/` стоит менять метку версии в путях к файлам в `index.html`
(`?v=...`) — иначе вебвью может подтянуть старый файл из кеша.

### Проверка ресурсов без Gradle

`aapt2` — нативный бинарник, Gradle ему не нужен:

```bash
D:\Android\Sdk\build-tools\34.0.0\aapt2.exe compile --dir android\app\src\main\res -o res-check.zip
```

### Про сборку из песочницы

Gradle не запускается в песочнице, где выполняются команды агента: Java NIO
не может создать `Selector`, и сборка падает с `Unable to establish loopback
connection`. В обычном терминале этой проблемы нет.
