# Галка: Планы и заметки — ежедневник с напоминаниями

## Версия 1.0.0 — первый выпуск

- календарь месяца с переходом к любой дате и лентой дел на день;
- выбор цвета оформления, по умолчанию белый;
- удаление всех данных с подтверждением словом и автоматической копией в «Загрузки»;
- задачи с произвольным набором дней: один день или сколько угодно, каждый закрывается отдельно;
- разделы с цветом и описанием, просмотр задач по разделам или по датам;
- напоминания: к задаче со временем, список на день, задачи без времени, сводка незакрытого;
- свои окна выбора времени, даты и вариантов вместо системных;
- обмен расписаниями через файл `.galka`: экспорт, импорт с добавлением или заменой;
- системная кнопка «Назад», подтверждение выхода, переход между вкладками свайпом;
- проверка обновлений, раздел поддержки, сведения о приложении.

Приложение под Android: календарь, задачи по проектам, локальные уведомления.
Данные хранятся только на телефоне, ни сервера, ни аккаунтов.

Интерфейс — обычные HTML/CSS/JS без сборщика, оболочка — Capacitor 6.
Уведомления идут через нативный `AlarmManager`, поэтому приходят и при закрытом приложении.

## Что где лежит

```
www/                 интерфейс: index.html, styles.css, store.js, notify.js, backup.js, app.js
android/             нативный проект — его и открывать в Android Studio
capacitor.config.json
devserver.js         локальный сервер для предпросмотра в браузере
build-preview.js     сборка www/ в один файл (только для витрины, в APK не идёт)
```

Логика разнесена так: `store.js` — данные и localStorage, `notify.js` — расписание
уведомлений, `backup.js` — обмен файлами, `app.js` — отрисовка и события.

## Обмен расписаниями: формат `.galka`

Синхронизации нет намеренно — она требует сервера и аккаунтов, а приложение
бесплатное. Перенос между устройствами и резервная копия делаются файлом.

Внутри обычный JSON с шапкой, читаемый глазами:

```json
{
  "format": "galka",
  "formatVersion": 1,
  "exportedAt": "2026-08-15T00:10:00.000Z",
  "app": { "versionName": "1.0.0", "versionCode": 1 },
  "counts": { "projects": 4, "tasks": 22, "groups": 9 },
  "data": { "projects": [], "tasks": [], "settings": {} }
}
```

Имя файла — `galka-ГГГГ-ММ-ДД.galka`.

**Экспорт.** `AppSettingsPlugin.exportFile` пишет файл в `cacheDir/export`, отдаёт его
через уже объявленный `FileProvider` и открывает системный выбор получателя. Каталог
чистится перед каждой выгрузкой, чтобы копии не накапливались.

**Импорт.** `AppSettingsPlugin.importFile` открывает системный выбор файла
(`ACTION_OPEN_DOCUMENT` с типом `*/*` — у `.galka` нет зарегистрированного MIME-типа)
и возвращает содержимое строкой. Файлы больше 8 МБ отклоняются.

В браузере оба действия работают через обычную загрузку и `<input type="file">`,
поэтому предпросмотр остаётся рабочим.

### Что происходит с данными

`Store.readBundle()` только разбирает и проверяет файл, ничего не меняя: отбивает
повреждённый JSON, чужой формат, файл от более новой версии и файл без задач.
Пользователь видит, сколько внутри задач и разделов, и лишь потом выбирает режим.

`Store.applyBundle()` умеет два режима:

- **добавить к текущим** — всем разделам, задачам и группам выдаются новые
  идентификаторы, ссылки «задача → раздел» и «задача → группа дней» перестраиваются.
  Существующие данные не затрагиваются;
- **заменить всё** — данные очищаются и загружаются заново. Требует отдельного
  подтверждения, потому что необратимо.

Оформление (тёмная или светлая тема) при замене не перезаписывается — оно относится
к телефону, а не к расписанию. Поля из файла санируются: цвета проверяются по маске,
даты и время по формату, длинные строки обрезаются.

## Задачи, дни и разделы

Сущностей всего две: **раздел** и **задача**. Отдельного объекта для повторяющейся
работы нет — и не нужно.

У задачи есть набор дней. Выбираются они календарём прямо в редакторе: тап по дню
или ведение пальцем по нескольким. Один день — разовая задача. Несколько — она встаёт
на каждый выбранный день, и каждый закрывается отдельно.

Так описывается любая повторяющаяся работа, без привязки к сфере: цикл учёбы,
серия тайтла, выпуск подкаста. Название задача получает от пользователя, приложение
своих слов не навязывает и никаких заготовок не предлагает.

Раздел — это папка с цветом. Внутри «Учёбы» спокойно живут «Цикл 1», «Цикл 2»
и «Зачёт». Вкладка «Задачи» группирует всё по разделам, у многодневных показывает
прогресс вида `2 / 5`.

### Как это устроено в данных

Дни одной задачи связаны общим `groupId`: на каждый день создаётся отдельная запись
в `tasks`, у всех них одинаковые `groupId`, название, раздел, время и напоминание.
Отличаются только `date` и `done`.

`Store.saveGroup()` принимает задачу целиком, вместе со списком дней:

- дни, оставшиеся в списке, сохраняют отметку о выполнении;
- снятые дни удаляются;
- добавленные создаются незакрытыми.

`Store.groups()` сворачивает записи обратно в задачи — это и есть то, что показывает
вкладка «Задачи». Удаление через `deleteGroup()` убирает все дни разом.

### Совместимость данных

Ранние версии держали расписания релизов и циклов как отдельную сущность.
`Store.load()` при чтении убирает `project.release`, `project.cycle` и `task.gen`,
а каждой задаче без `groupId` выдаёт свой. Ранее созданные задачи остаются на своих
датах и становятся обычными разовыми.

## Подпись и выпуск версий

### Ключ

Обновление обязано быть подписано тем же ключом, что и установленная версия,
иначе Android откажется ставить его поверх. Потеря ключа означает, что всем
придётся удалять приложение и терять задачи — они лежат в хранилище вебвью
и уходят вместе с ним.

Ключ создаётся один раз и хранится вне репозитория:

```bash
& 'C:\Program Files\Eclipse Adoptium\jdk-17.0.1.12-hotspot\bin\keytool.exe' -genkeypair -v -keystore D:\Android\keys\galka-release.jks -alias galka -keyalg RSA -keysize 4096 -validity 10000
```

Дальше рядом с проектом создаётся файл `android/keystore.properties`:

```
storeFile=D:/Android/keys/galka-release.jks
storePassword=пароль хранилища
keyAlias=galka
keyPassword=пароль ключа
```

Пути пишутся через прямую косую черту: обратную Gradle прочитает как экранирование.
И `.jks`, и `keystore.properties` перечислены в `.gitignore` — в репозиторий они не попадают.
Образца этого файла в проекте намеренно нет, чтобы пароль некуда было вписать по ошибке.

Отпечаток сертификата, которым подписан релиз:

```
SHA-256: d47a70456ac5aee8473ff1214d2271958bfc1070a2a3a586a03490f272af1ca7
```

Проверить подпись собранного APK:

```bash
& 'D:\Android\Sdk\build-tools\34.0.0\apksigner.bat' verify --print-certs android\app\build\outputs\apk\release\app-release.apk
```

`android/app/build.gradle` подхватывает их сам. Если файла нет, сборка не падает:
`release` просто остаётся без подписи, а `debug` работает как раньше.

Собрать подписанный APK:

```bash
cd D:\Projects\dayplan\android; .\gradlew.bat assembleRelease
```

Результат: `android/app/build/outputs/apk/release/app-release.apk`

### Выпуск

1. Поднять `versionCode` и `versionName` в `android/app/build.gradle`.
   `versionCode` обязан расти, иначе установка поверх не пройдёт.
2. Собрать `assembleRelease`.
3. Создать релиз на GitHub и приложить APK файлом.
4. Обновить `update.json` в корне репозитория: `versionCode`, `versionName`,
   `notes` и `downloadUrl` со ссылкой на APK из релиза.

Приложение сравнивает `versionCode` из файла с установленным и предлагает
скачать обновление. Адрес файла задаётся в `APP_LINKS.updateManifest` (`www/app.js`).

## Сборка APK

Android SDK уже установлен в `D:\Android\Sdk`, путь прописан в `android/local.properties`.
Заново скачивать SDK не нужно — Android Studio его подхватит.

1. Открыть в Android Studio папку **`D:\Projects\dayplan\android`** (именно её, не корень проекта).
2. Сразу после открытия задать каталог Gradle:
   *Settings → Build, Execution, Deployment → Build Tools → Gradle → Gradle user home* →
   **`D:\Android\gradle-home`**.
   Туда уже скачан Gradle 8.2.1 со всеми зависимостями — иначе Studio потянет около
   гигабайта заново в `C:\Users\Птахен\.gradle`, где вдобавок кириллица в пути.
3. Дождаться Gradle sync.
4. *Build → Build Bundle(s) / APK(s) → Build APK(s)*.

Готовый файл: `android/app/build/outputs/apk/debug/app-debug.apk`

APK подписан отладочным ключом. Для установки на свой телефон этого достаточно,
для публикации в Play понадобился бы релизный ключ.

## Установка на телефон

Перекинуть APK на телефон, открыть, разрешить установку из неизвестных источников.

Дальше — три вещи, без которых Android будет глушить напоминания:

1. Разрешение на уведомления — открыть «Настройки → Уведомления → Разрешение на уведомления».
2. Точные будильники — проверить в настройках приложения, строка
   «Точное время срабатывания». На Android 13+ выдаётся автоматически.
3. **Батарея.** Настройки телефона → Приложения → Галка: Планы и заметки → Батарея → **Без ограничений**.
   На Xiaomi, Samsung и Huawei без этого система усыпляет приложение и будильники не срабатывают.

Проверить, что всё работает: в настройках приложения кнопка
«Прислать проверочное уведомление» отправляет его сразу.

## Правка интерфейса

```bash
node devserver.js
```

Открыть `http://localhost:5173`, править файлы в `www/`, обновлять страницу.
Уведомления в браузере не отправляются — код это учитывает и молча пропускает их.

После правок перенести изменения в нативный проект:

```bash
npx cap sync android
```

и пересобрать APK.

## Про сборку из командной строки

Gradle не запускается в песочнице, где выполняются команды агента: Java NIO не может
создать `Selector` (внутренняя пара loopback-сокетов), и сборка падает с
`Unable to establish loopback connection`. В обычном терминале этой проблемы нет:

```bash
cd D:\Projects\dayplan\android
$env:JAVA_HOME='C:\Program Files\Eclipse Adoptium\jdk-17.0.1.12-hotspot'
$env:ANDROID_HOME='D:\Android\Sdk'
$env:GRADLE_USER_HOME='D:\Android\gradle-home'
.\gradlew.bat assembleDebug
```

## Проверка ресурсов без Gradle

Валидность XML-ресурсов (векторные иконки, строки, цвета) можно проверить напрямую —
это нативный бинарник, Gradle ему не нужен:

```bash
D:\Android\Sdk\build-tools\34.0.0\aapt2.exe compile --dir android\app\src\main\res -o res-check.zip
```
